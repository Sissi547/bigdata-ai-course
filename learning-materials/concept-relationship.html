大模型、Agent、Skill 与上下文：
四个概念到底什么关系？

统一类比贯穿全文：大模型是脑子，Agent 是用这个脑子干活的人，上下文是这个人此刻桌上的白板，Skill 是他口袋里的岗位手册。（需要联网加载关系图）

脑子想 · 白板看 · 口袋装 · 一双手干活

三、重点一：上下文如何影响 Agent 的工作

Anthropic 对 Agent 的定义是"在循环中根据环境反馈使用工具的大语言模型"。这个循环的每一步，模型能依据的只有白板上写了什么：

flowchart LR A[读白板] --> B[想：下一步干嘛] B --> C[动手：调用工具] C --> D[结果写回白板] D --> A D -.->|任务完成| E[✅ 结束]
白板（上下文）的状态对 Agent 工作的影响
目标清楚、有重点决策方向准，一次到位
关键信息塞在中间容易被忽略（IBM 引用的研究：开头结尾记得牢，中间最易漏）
塞满旧对话、垃圾输出注意力预算被摊薄，context rot——越满越记不准
缺少必要资料只能瞎猜 → 幻觉
有精炼的指令和手册行为稳定、符合规范
同一句"帮我订会议室"：白板上有课表查询结果，Agent 直接订好汇报；白板上没有，它只能让你自己看看教室。差别不在脑子，在白板。

四、重点二：Skill 如何沉淀可复用的任务知识

Agent 干活产生的"经验"，如果不记下来，下次对话开始就归零。Skill 把这些经验写进文件、存进口袋：

flowchart LR A[🧑‍💻 Agent 干活] --> B[发现好做法/踩了坑] B --> C{要不要沉淀?} C -->|一次性任务| D[不沉淀，经验消失] C -->|会重复做的事| E[✍️ 写成 SKILL.md] E --> F[📁 存入技能文件夹
不占白板] F -->|下次遇到同类任务| G[🔍 按描述匹配] G --> H[📖 翻开手册，加载进白板] H --> I[✅ 稳定复现：不走样、不遗漏] I --> A

沉淀的含义：把一次性的、留在聊天记录里的隐式经验，变成版本化的、可分享的显式知识——写一次，人人可用，次次可用。

Skill 的三层占白板多少作用
第 1 层：name + description（封面）极小（每技能约 100 token）知道口袋里有哪些手册、各管什么
第 2 层：SKILL.md 正文（做法）任务匹配时才加载照着做，结果稳定
第 3 层：脚本 / 参考资料 / 模板确有需要才读细节按需取用
装几十本手册，平时只有"封面目录"上白板——既知道有什么可用，又不挤占干活空间。这就是"沉淀"与"预算"的完美配合。

五、三者协作的完整闭环

sequenceDiagram participant U as 用户 participant A as Agent participant C as 上下文（白板） participant S as Skill 库（口袋） U->>A: 目标："整理读书会纪要" A->>C: 目标上板 + 查口袋封面 A->>S: 发现"整理笔记"手册匹配 S-->>C: 只翻出这一页（省预算） loop 循环：干一步→看反馈→再干 A->>C: 读白板决定下一步 A->>A: 调用工具执行 A->>C: 结果写回白板 end A->>U: ✅ 交付结果 A->>S: 新经验写成手册页，沉淀入库

六、总结

Agent 用大模型当脑子，凭上下文这块白板做每一个决定；
Skill 把干过的好做法写成手册存进口袋，需要时再翻开一页放回白板。
白板决定它干得多准，手册决定它干得多稳。
