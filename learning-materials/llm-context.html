大模型的"上下文"入门

小智怎么突然忘了读书会是周五？这一讲用一块白板，讲清楚 AI 的"记性"是怎么回事。

一个尴尬场景 一块白板 两个坑 三大招 + 5 道小题

内容依据 Anthropic《Effective Context Engineering》与 IBM《What is a context window?》· 方向键翻页

尴尬场景

"读书会是哪天来着？"

我
（下午先说了读书会定在周五，又聊了书目、教室、零食……聊到第 100 条）所以读书会是哪天来着？
智
您还没告诉我日期呢。
它不是装傻——是那句话已经"掉出它的视野"了。要理解这件事，得先认识一个词：上下文。
核心概念

上下文 = AI 此刻"看得见"的一切

IBM 的定义很直白：上下文窗口就是模型一次能"记住"的内容总量，相当于它的工作记忆。想象小智面前有一块白板：

白板上现在有： ① 任务说明书 ← 隐藏的"系统提示"（比如：你是小智，语气友好） ② 你我说过的所有对话 ③ 刚刚查到的资料、工具返回的结果 ④ 你上传的文件内容
回答问题时，它只看白板。没写在白板上的，对它来说就不存在。
白板多大

容量按"积木块"（token）计数

AI 读文字前会先把文字切成小块，每块叫一个 token（词元）——像一个词、半个词或一个字，是 AI 的"积木块"。

≈ 十几页文档

8,000 token

≈ 一本两百页的书

128,000 token

≈ 一整套长篇小说

2,000,000 token

换算参考（IBM）：英文约 1.5 个 token 一个单词；中文一个字约 1~2 个 token。2022 年 ChatGPT 刚上线只有约 4 千 token，现在主流模型 12.8 万起步——进步飞快。

注意：白板上不只有你打的字——说明书、查询结果、文件，甚至换行符都在占地方。

两个坑

白板越大越好吗？不是

坑一：越大越贵、越慢

IBM 算过账：输入翻一倍，需要的算力翻四倍。而且 AI 每写一个字都要"看一遍白板全部"，白板越满回答越慢。

坑二：太满了反而"看不准"

Anthropic 称之为 context rot（上下文"腐烂"）：白板越满，准确想起其中某条信息的能力越差。研究还发现：开头和结尾记得牢，塞在中间的最容易被忽略——像人看超长的会议记录。

上下文是"注意力预算"：每多塞一条，预算就少一分
长活儿怎么办

Anthropic 的三大招

第一招：压缩

白板快满了，把内容总结成几行要点，换块新白板只写要点接着干。——像散会前记一页会议纪要。

第二招：记笔记

把重要的事写到白板外面的本子上，要用时再抄回来。——像便利贴。Anthropic 让 AI 玩宝可梦，它靠自发记笔记，白板被清空后还能接着打几小时比赛。

第三招：派小弟

让几个"分身"各自去翻资料，只把结论带回来，翻垃圾的过程不占主白板。——像老板只要一页汇报，不要整个图书馆。

原来前几课一直在"省白板"

📔 Skill 分三层按需加载 —— 就是为了不把整本手册塞上白板
📏 Skill 正文别超 500 行 —— 卡太长会占掉太多注意力预算
🧑‍💻 Agent 干长活不出错 —— 靠"记笔记"把进度存到白板外面

模型是脑子，Agent 是能干活的人，Skill 是口袋手册
上下文是桌上的白板 —— 所有聪明表现，都来自白板上写了什么
马上能用

新手的 4 个技巧

1. 重要的话放在开头或结尾说（中间最容易被忽略）
2. 聊了很久，先让 AI 总结一下目前的要点再继续
3. 新任务开新对话，别让旧杂物占白板
4. 长任务让 AI 写笔记："把刚才确定的事项记成清单"
