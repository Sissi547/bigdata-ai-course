为什么学 · 5 分钟

每天几百条来稿，谁先分好类？

编辑部每天收到校园来稿，要分到体育、学术、生活等不同栏目。人工分要一条条看；而分类器可以做到：给一条新标题，直接告诉你"这更像体育版"。

情感分析回答"感觉好不好"；文本分类回答"属于哪一类"。两者都是把文字变成计算机能处理的东西，只是目标不同。
理论 · 6 分钟

朴素贝叶斯的直觉：关键词投票

朴素贝叶斯
一种经典分类方法。核心直觉：看哪些词出现过，按"这些词在各类型里的常见程度"投票，票多的获胜。
"校运会百米决赛破纪录" 含"决赛""破纪录" → 在体育类稿件里极常见 → 投给体育 "实验室发表最新研究成果" 含"实验室""研究成果" → 在学术类里常见 → 投给学术
为什么叫"朴素"？因为它假设每个词之间互不相关——现实里明显不成立（"百米"和"决赛"高度相关），但这个"朴素"的假设在文本分类上意外地好用，而且快。这就是它几十年不衰的原因。
理论 · 5 分钟

两个动作：训练与预测

1
训练（fit）

把"已分好类的历史稿件"喂给程序，让它统计：体育类里各词出现频率如何、学术类又如何。

2
预测（predict）

给它一条从没见过的新标题，它按学到的频率投票，给出类别。

3
评估（score）

用一批"知道答案"的标题考它，算准确率——这就是模型的成绩单。

还记得概念 02 讲的"从数据中学规律"吗？fit 就是"学"，predict 就是"用"，score 就是"考试"——今天你亲手把这套流程跑一遍。
实操 · 15 分钟

动手：20 行训练一个新闻分类器

先安装（国内源已配好）：

pip install scikit-learn jieba
from sklearn.feature_extraction.text import CountVectorizer from sklearn.naive_bayes import MultinomialNB # ① 训练数据：已经分好类的历史稿件（越多越准，这里只是示例） texts = [ "校运会百米决赛破纪录", "篮球联赛主场大胜", "足球队员加练体能", "实验室发表最新研究成果", "学术讲座报名开始", "论文被国际会议录用", ] labels = ["体育", "体育", "体育", "学术", "学术", "学术"] # ② 把文字变成数字表格（概念 04 的词袋） vectorizer = CountVectorizer() X = vectorizer.fit_transform(texts) # ③ 训练 + 预测 model = MultinomialNB() model.fit(X, labels) new_titles = ["田径队备战下月校运会", "课题组获批新的科研项目"] X_new = vectorizer.transform(new_titles) # 注意：用同一个 vectorizer for t, p in zip(new_titles, model.predict(X_new)): print(f"{p} ← {t}")
三行核心代码对应三个概念：CountVectorizer 是概念 04 的词袋，MultinomialNB 是本页的朴素贝叶斯，fit / predict 是训练与预测。AI 库用起来就这么几行——难的是理解它为什么有效、以及何时会失灵。
诚实提醒 · 4 分钟

样本太少会怎样？

示例只有 6 条

它能跑通、能输出结果，但这个"模型"几乎没有实用价值——数据太少，规律学不到。跑通 ≠ 可用。

要多少才像样？

真实项目通常是每类几百到几千条，还要留一部分数据专门用来"考试"（评估准确率），不能拿训练数据自夸。

这是本课程最重要的一条职业素养：任何模型结果都要说明数据来源与样本量，并保留人工复核。这和新闻"信源核实"是同一种严谨。
